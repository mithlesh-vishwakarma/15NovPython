JavaScript Essentials & Advanced — Interview Answers
Prepared for your mock interview — 52 questions, explained simply with examples.

1. What is JavaScript, and how does it differ on client side vs server side?
JavaScript is a programming language that makes web pages interactive. Think of HTML as the skeleton, CSS as the clothes, and JavaScript as the muscles that make things move.

Client-side JS runs in the user's browser. It can touch the DOM (buttons, forms, images), react to clicks, and update the page without reloading.
Server-side JS (via Node.js) runs on a server. It has no access to the browser DOM, but it can access things a browser can't — the file system, databases, and can serve multiple users at once.
Quick line to say in interview: "Same language, two different environments — browser JS talks to the page, Node.js talks to the server."

2. How do you include JavaScript in an HTML page?
Using the <script> tag.

<!-- Inline -->
<script>
  console.log("Hello!");
</script>

<!-- External file -->
<script src="app.js"></script>
Best practice: place <script> just before </body>, or use the defer attribute in <head>, so the HTML loads first and JS doesn't block rendering.

<head>
  <script src="app.js" defer></script>
</head>
3. Where can you quickly test a line of JavaScript in your browser?
The browser console — part of Developer Tools (F12, or right-click → Inspect → Console tab). You can type any JS there and hit Enter to run it instantly. Great for quick experiments and debugging.

4. Difference between var, let, and const
Feature	var	let	const
Scope	Function-scoped	Block-scoped	Block-scoped
Reassignable	Yes	Yes	No
Redeclarable	Yes	No	No
Hoisting	Hoisted, initialized as undefined	Hoisted, but in "temporal dead zone"	Same as let
var x = 1;   // old way, avoid — leaks outside blocks
let y = 2;   // use when the value will change
const z = 3; // use by default, when the value won't be reassigned
Simple rule to say: "I default to const, use let when I need to reassign, and avoid var entirely."

5. Primitive vs reference data types
Primitive types (string, number, boolean, null, undefined, symbol, bigint) are stored by value. Copying them creates an independent copy.
Reference types (objects, arrays, functions) are stored by reference. Copying them copies the address, not the data — so both variables point to the same thing.
let a = 5;
let b = a;
b = 10;
console.log(a); // 5 — untouched

let obj1 = { name: "Sam" };
let obj2 = obj1;
obj2.name = "Alex";
console.log(obj1.name); // "Alex" — changed too!
Analogy: primitives are like handing someone a photocopy; objects are like handing someone the key to the same house.

6. Example of dynamic typing
JavaScript doesn't require you to declare a variable's type — and a variable can hold different types over its life.

let value = 42;        // number
value = "now a string"; // string — no error!
value = true;           // boolean

8. == vs ===
== (loose equality) compares values after converting types if they differ.
=== (strict equality) compares value AND type, no conversion.
0 == '0'     // true  (string converted to number)
0 === '0'    // false (different types)
null == undefined  // true
null === undefined // false
Best practice: always use === to avoid unexpected type coercion bugs.

9. What is a "truthy" value?
A value that behaves like true when evaluated in a boolean context (like an if statement), even though it isn't literally the boolean true.

if ("hello") { console.log("This runs!"); } // non-empty string is truthy
if (42) { console.log("This runs too!"); }  // any non-zero number is truthy
The only falsy values in JS are: false, 0, "", null, undefined, NaN. Everything else is truthy.

10. For loop over an array
let links = ['Instagram', 'Twitter', 'LinkedIn'];

for (let i = 0; i < links.length; i++) {
  console.log(links[i]);
}
11. for loop vs forEach
for loop: full manual control — you control the index, can break/continue, and it works on any iterable.
forEach: an array method built for readability. Cleaner syntax, but you cannot break out of it early.
links.forEach(link => console.log(link));
Rule of thumb: use forEach for simple iteration; use a regular for loop when you need to stop early or need the index for complex logic.

12. Function declaration: greetUser
function greetUser(name) {
  return `Hello, ${name}!`;
}

console.log(greetUser("Mithlesh")); // "Hello, Mithlesh!"
13. Function declaration vs function expression
// Declaration — hoisted, can be called BEFORE it's defined in the code
function sayHi() { console.log("Hi"); }

// Expression — NOT hoisted the same way, must be defined before use
const sayBye = function() { console.log("Bye"); };
Key point: function declarations are fully hoisted (name + body). Function expressions are only hoisted as a variable — calling them before the line they're defined on throws an error.

17. onclick vs addEventListener
// onclick — only ONE handler allowed; overwrites any previous one
button.onclick = function() { console.log("Clicked"); };

// addEventListener — can attach MULTIPLE handlers, more flexible
button.addEventListener('click', function() { console.log("Clicked"); });
addEventListener is the modern, preferred approach — it also lets you remove listeners and control event phases (capturing/bubbling).

18. The event object
When an event fires (click, keypress, submit...), the browser automatically passes an event object to your handler, containing details about what happened.

button.addEventListener('click', function(event) {
  console.log(event.target);   // the exact element clicked
  console.log(event.type);     // "click"
});
Common uses: event.preventDefault() (stop default browser behavior), event.target (what triggered it), event.key (which key was pressed).

21. JSON.stringify() and JSON.parse()
JSON.stringify(obj): converts a JS object/array into a JSON string (needed to save to localStorage or send over a network — both only handle text).
JSON.parse(str): converts a JSON string back into a real JS object/array.
const obj = { name: "Sam" };
const str = JSON.stringify(obj); // '{"name":"Sam"}'
const backToObj = JSON.parse(str); // { name: "Sam" }
22. Save links to localStorage and retrieve them
// Save
localStorage.setItem('links', JSON.stringify(socialLinks));

// Retrieve
const saved = JSON.parse(localStorage.getItem('links')) || [];
Since localStorage only stores strings, you must stringify before saving and parse after reading.

23. Template literals
Template literals use backticks (`) instead of quotes, and let you embed variables directly with ${} — no more + concatenation.

const name = "Sam";
// Old way
console.log("Hello, " + name + "!");
// Template literal
console.log(`Hello, ${name}!`);
They also support multi-line strings naturally, without \n.

24. Destructuring an object
let link = { title: 'GitHub', url: 'https://github.com' };
const { title, url } = link;

console.log(title); // "GitHub"
console.log(url);   // "https://github.com"
Destructuring pulls values out of an object into their own named variables in one line.

25. The spread operator (...)
... "unpacks" the contents of an array or object — useful for copying or merging without mutating the original.

const arr1 = [1, 2, 3];
const arr2 = [...arr1, 4, 5]; // [1, 2, 3, 4, 5] — arr1 untouched

const objA = { a: 1 };
const objB = { ...objA, b: 2 }; // { a: 1, b: 2 }
26. Blocking vs non-blocking code
Blocking: each line waits for the previous one to fully finish before running. Slow operations (like a large file read) freeze everything else.
Non-blocking (asynchronous): slow operations run in the background, and the rest of the code keeps executing — the result is handled later (via callbacks, promises, or async/await).
JavaScript is single-threaded but uses an event loop to handle non-blocking operations like fetch, setTimeout, and file reads.

27. Callback function example
A callback is a function passed into another function, to be run later (often after some delay or event).

function sayHello() {
  console.log("Hello after 2 seconds!");
}

setTimeout(sayHello, 2000); // sayHello is the callback
28. Promise that resolves after 2 seconds
const delayedMessage = new Promise((resolve) => {
  setTimeout(() => {
    resolve('Done!');
  }, 2000);
});

delayedMessage.then(message => console.log(message)); // "Done!" after 2s
29. How fetch() works
fetch() makes an HTTP request to a URL and returns a Promise. The general flow:

Call fetch(url) — sends the request, returns a Promise.
The Promise resolves to a Response object once headers arrive.
Call .json() (or .text()) on the response — this is also a Promise — to parse the actual body.
Handle the final data in another .then(), or use try/catch with async/await.
fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
30. Fetch users from JSONPlaceholder
fetch('https://jsonplaceholder.typicode.com/users')
  .then(response => response.json())
  .then(users => console.log(users))
  .catch(error => console.error('Fetch error:', error));

// Or with async/await:
async function getUsers() {
  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/users');
    const users = await response.json();
    console.log(users);
  } catch (error) {
    console.error('Fetch error:', error);
  }
}

31. Default exports vs named exports (ES6 modules)
// file: utils.js

// Named export — can have MANY per file, imported with exact matching names in {}
export function add(a, b) { return a + b; }

// Default export — only ONE per file, imported with ANY name, no {}
export default function multiply(a, b) { return a * b; }
// importing:
import multiply, { add } from './utils.js';
32. Why modularize JavaScript code?
Reusability — write a function once, use it anywhere.
Readability — each file has one clear responsibility, easier to navigate.
Maintainability — fixing a bug in one module doesn't force you to scroll through thousands of lines.
Team collaboration — different people can work on different files without conflict.
Avoids global scope pollution — variables stay contained to their module.
33. Move a utility function to another file and use it
// mathUtils.js
export function double(num) {
  return num * 2;
}
// main.js
import { double } from './mathUtils.js';

console.log(double(5)); // 10
Note: when using ES6 modules in the browser, your <script> tag needs type="module".

34. Declaring a class — UserProfile

35. Purpose of try...catch
try...catch lets you run code that might fail, and gracefully handle the error instead of crashing the whole app.

try {
  JSON.parse("this is not valid JSON");
} catch (error) {
  console.log("Something went wrong:", error.message);
}
Use it around things like JSON parsing, API calls, or any operation with unpredictable input.

36. Throw a custom error for an invalid URL
function validateUrl(url) {
  if (!url.startsWith('http')) {
    throw new Error('URL must start with http');
  }
  return true;
}

try {
  validateUrl('ftp://example.com');
} catch (error) {
  console.log(error.message); // "URL must start with http"
}

38. What does map() do?
map() creates a new array by transforming every element with a function — it doesn't change the original array.

const numbers = [1, 2, 3];
const doubled = numbers.map(n => n * 2); // [2, 4, 6]

40. find() vs filter()
find(): returns the first matching element (a single item, or undefined if none match).
filter(): returns all matching elements as a new array (empty array if none match).
const arr = [1, 2, 3, 4];
arr.find(n => n > 2);   // 3 (just the first match)
arr.filter(n => n > 2); // [3, 4] (all matches)
41. What is event delegation?
Instead of attaching a separate event listener to every child element, you attach one listener to a parent and use event.target to figure out which child was actually clicked.

Why it's useful: elements added later (dynamically) are automatically covered too, since the listener lives on the parent, not the (possibly not-yet-existing) child.

document.getElementById('linkList').addEventListener('click', function(event) {
  console.log('Clicked:', event.target.textContent);
});
42. Remove a card when its "X" button is clicked (via delegation)
document.getElementById('cardContainer').addEventListener('click', function(event) {
  if (event.target.classList.contains('delete-btn')) {
    const card = event.target.closest('.card');
    card.remove();
  }
});
event.target tells us exactly what was clicked; .closest('.card') walks up to find the whole card to remove.

43. Two console methods for debugging
console.log() — prints general values/messages, the everyday debugging tool.
console.table() — displays arrays/objects as a readable table, great for arrays of objects.
(Bonus) console.error() — prints in red, useful for flagging real problems distinctly from normal logs.
44. Setting a breakpoint in DevTools
In the browser's DevTools Sources tab, click on the line number next to the code you want to pause on. When execution reaches that line, it pauses, letting you:

Inspect variable values at that exact moment.
Step through code line-by-line (Step Over, Step Into).
See the call stack (which functions called which).
This is far more precise than sprinkling console.log() everywhere.

45. Planning data flow for an add/edit/delete links app
State: keep a single source of truth — an array of link objects ({ id, title, url }) in memory (and synced to localStorage).
Render: a function reads that array and builds the DOM list from scratch (or updates it) each time state changes.
Add: form submit → validate → push new object to array → re-render → save to localStorage.
Edit: find the item by id → update its fields → re-render → save.
Delete: filter the item out by id → re-render → save.
Key principle: the array is the single source of truth; the UI always reflects it, never the other way around.

46. Debugging: clicking "Add" sometimes adds two identical links
Steps to investigate:

Check for duplicate event listeners — is addEventListener being called more than once on the same button (e.g., inside a function that re-runs)?
Check for form default behavior — is event.preventDefault() missing, causing an actual page submit plus your JS handler both firing?
Add a console.log inside the handler to see how many times it actually runs per click.
Check double-binding on re-render — if you rebuild the DOM and re-attach listeners without removing old ones first, they stack up.
Fix pattern: attach the listener once (outside any re-render loop), and always call event.preventDefault() in form submissions.

47. Validate a URL input and show an error

50. Integrative: destructuring + array methods to extract URLs

52. Integrative: classes + event listeners + localStorage for persisted links
class LinkManager {
  constructor() {
    this.links = JSON.parse(localStorage.getItem('links')) || [];
  }

  addLink(title, url) {
    this.links.push({ title, url });
    this.save();
  }

  save() {
    localStorage.setItem('links', JSON.stringify(this.links));
  }

  render() {
    const list = document.getElementById('linkList');
    list.innerHTML = '';
    this.links.forEach(link => {
      const li = document.createElement('li');
      li.textContent = `${link.title}: ${link.url}`;
      list.appendChild(li);
    });
  }
}

const manager = new LinkManager();
manager.render();

document.getElementById('addLinkBtn').addEventListener('click', () => {
  const title = document.getElementById('titleInput').value;
  const url = document.getElementById('urlInput').value;
  manager.addLink(title, url);
  manager.render();
});
This ties everything together: a class manages state, event listeners react to user actions, and localStorage makes the data survive a page refresh.
