1. THE CORE FOUNDATION: SYNCHRONOUS VS ASYNCHRONOUS JAVASCRIPT
================================================================================

--------------------------------------------------------------------------------
1.1 What is Synchronous Code? (Single-Threaded & Blocking)
--------------------------------------------------------------------------------
* JavaScript is a SINGLE-THREADED language.
  That means it has only ONE brain (one call stack) and can do only ONE thing
  at a time.

* In Synchronous execution:
  - Code runs line by line, from top to bottom.
  - Line 2 cannot start until Line 1 finishes.
  - If Line 1 takes 10 seconds (e.g. downloading a huge file), the whole
    browser freezes and waits. This is called "BLOCKING".

  Example:
  ------------------------------------------------------------------------------
  console.log("Step 1: Wake up");
  console.log("Step 2: Brush teeth");
  console.log("Step 3: Go to work");
  ------------------------------------------------------------------------------
  Output:
  Step 1: Wake up
  Step 2: Brush teeth
  Step 3: Go to work
  (Guaranteed order, predictable, but can block if something takes time.)


--------------------------------------------------------------------------------
1.2 What is Asynchronous Code? (Non-blocking)
--------------------------------------------------------------------------------
* In Asynchronous execution:
  - Long-running operations (fetching data from server, waiting for a timer,
    reading a database) are started in the background.
  - JavaScript does NOT freeze while waiting. It continues executing the next
    lines of code immediately!
  - When the background task finishes, JS runs a notification/handler function
    to give you the result.

  Example:
  ------------------------------------------------------------------------------
  console.log("1. Placed order for pizza");

  // Simulating waiting 3 seconds for pizza:
  setTimeout(() => {
    console.log("2. Pizza arrived! Time to eat!");
  }, 3000);

  console.log("3. Chatting with friends while waiting...");
  ------------------------------------------------------------------------------
  Output:
  1. Placed order for pizza
  3. Chatting with friends while waiting...
  (after 3 seconds)
  2. Pizza arrived! Time to eat!

  Notice: Step 3 ran BEFORE Step 2! JS didn't stop and wait for the 3 seconds.


--------------------------------------------------------------------------------
1.3 Real-World Restaurant Analogy
--------------------------------------------------------------------------------
* SYNCHRONOUS RESTAURANT:
  - Waiter takes Customer A's order.
  - Waiter goes to kitchen and STANDS THERE doing nothing for 20 minutes until
    the food is cooked.
  - Customer B, C, and D are standing in line outside, starving and angry.
  - Extremely inefficient!

* ASYNCHRONOUS RESTAURANT (The Real JavaScript Way):
  - Waiter takes Customer A's order and passes it to the chef (background).
  - Waiter hands Customer A a buzzer/token.
  - Waiter immediately serves Customer B and Customer C.
  - When Customer A's food is ready, the buzzer beeps (callback/promise triggers)
    and Customer A gets their food.


--------------------------------------------------------------------------------
1.4 How JavaScript Handles Async Behind the Scenes
--------------------------------------------------------------------------------
JavaScript uses four key pieces in the browser runtime:

  1. CALL STACK:
     Where your code actually gets executed, one function at a time.
  2. WEB APIs (Browser Background Engine):
     Where timers (`setTimeout`), network requests (`fetch`), and DOM events live
     while they are waiting.
  3. CALLBACK / TASK QUEUE:
     Where finished asynchronous tasks wait in line to be executed.
  4. EVENT LOOP:
     A continuous supervisor. It checks: "Is the Call Stack empty? If yes, take
     the first waiting task from the Queue and push it onto the Call Stack!"

2. TOPIC 1: CALLBACK FUNCTIONS
================================================================================

--------------------------------------------------------------------------------
2.1 What is a Callback Function?
--------------------------------------------------------------------------------
DEFINITION:
A Callback Function is simply a function that is PASSED AS AN ARGUMENT to
another function, to be executed ("called back") at a later time.

SIMPLE ANALOGY:
You visit a mechanic to fix your car. You say: "Here is my car. And here is my
phone number. When you finish fixing it, CALL ME BACK."
Your phone number + action is the callback function!

KEY RULE IN JAVASCRIPT:
In JS, functions are "First-Class Citizens". That means functions can be:
1. Stored in variables.
2. Passed as arguments into other functions.
3. Returned from functions.


--------------------------------------------------------------------------------
2.2 Synchronous Callbacks vs Asynchronous Callbacks
--------------------------------------------------------------------------------
1. SYNCHRONOUS CALLBACK:
   Executes immediately during the parent function's run.
   Example: Array methods like `.map()`, `.filter()`, `.forEach()`

   ```javascript
   const numbers = [1, 2, 3];
   // The arrow function (n => n * 2) is a synchronous callback
   const doubled = numbers.map(n => n * 2);
   console.log(doubled); // [2, 4, 6]
   ```

2. ASYNCHRONOUS CALLBACK:
   Executes after some background event or delay completes.
   Example: `setTimeout`, event listeners, reading files.

   ```javascript
   console.log("Start");
   setTimeout(function() {
     console.log("Executed 2 seconds later!");
   }, 2000);
   console.log("End");
   ```


--------------------------------------------------------------------------------
2.3 How to Create and Use a Callback (Step-by-Step)
--------------------------------------------------------------------------------
Let's build a custom function that takes a callback:

```javascript
// Step 1: Define a function that accepts another function (callback) as a parameter
function greetUser(name, callbackFunction) {
  console.log("Hello, " + name + "!");
  // Step 2: Call the callback function!
  callbackFunction();
}

// Step 3: Define the callback function
function sayGoodbye() {
  console.log("Goodbye! Have a nice day.");
}

// Step 4: Pass sayGoodbye into greetUser (NOTICE: DO NOT use parentheses sayGoodbye()!)
greetUser("Rahul", sayGoodbye);

/*
Output:
Hello, Rahul!
Goodbye! Have a nice day.
*/
```

CRITICAL TIP:
Notice we wrote `greetUser("Rahul", sayGoodbye)` and NOT `sayGoodbye()`.
- `sayGoodbye` = passing the function definition itself.
- `sayGoodbye()` = calling it immediately! (Which returns undefined).


--------------------------------------------------------------------------------
2.4 Passing Data Through Callbacks (Simulating an Async Database Query)
--------------------------------------------------------------------------------
In real web development, callbacks are used to return data fetched from an API
or database:

```javascript
// Function simulating fetching user data from a server (takes 2 seconds)
function fetchUserData(userId, callback) {
  console.log("Fetching data from server for User ID: " + userId + "...");

  setTimeout(() => {
    // Simulated data returned from database
    const user = {
      id: userId,
      name: "Aarav Sharma",
      role: "Full-Stack Developer"
    };

    // Pass the fetched user data back via the callback
    callback(user);
  }, 2000);
}

// Consuming the function:
fetchUserData(101, function(user) {
  console.log("Data received successfully!");
  console.log("User Name:", user.name);
  console.log("User Role:", user.role);
});

/*
Console Timeline:
(Immediate): Fetching data from server for User ID: 101...
(After 2s):  Data received successfully!
             User Name: Aarav Sharma
             User Role: Full-Stack Developer
*/
```

3. TOPIC 2: THE PROBLEM — CALLBACK HELL (PYRAMID OF DOOM)
================================================================================

--------------------------------------------------------------------------------
3.1 What is Callback Hell?
--------------------------------------------------------------------------------
DEFINITION:
Callback Hell refers to a situation where multiple asynchronous operations are
nested inside each other as callbacks.

As each step depends on the previous step's result, the code grows horizontally
to the right in a triangle shape (`>`).

It is also famously called:
- "The Pyramid of Doom"
- "The Christmas Tree Problem"


--------------------------------------------------------------------------------
3.2 Real-World Scenario: Online Food Delivery Workflow
--------------------------------------------------------------------------------
Imagine ordering food on Swiggy / Zomato. The steps MUST happen in exact order:
  Step 1: Select restaurant & place order (takes 2s)
  Step 2: Process the online payment (takes 2s)
  Step 3: Chef prepares the food (takes 3s)
  Step 4: Delivery partner picks up and delivers (takes 2s)

Look at what this code looks like using Callbacks:

```javascript
function placeOrder(item, callback) {
  setTimeout(() => {
    console.log("1. Order placed for:", item);
    callback(item);
  }, 1000);
}

function processPayment(item, callback) {
  setTimeout(() => {
    console.log("2. Payment successful for:", item);
    callback(true);
  }, 1000);
}

function prepareFood(item, callback) {
  setTimeout(() => {
    console.log("3. Food prepared:", item);
    callback("Food Parcel");
  }, 1000);
}

function deliverFood(parcel, callback) {
  setTimeout(() => {
    console.log("4. Delivered to customer:", parcel);
    callback("Order Completed!");
  }, 1000);
}

// =====================================================================
// HERE IS THE CALLBACK HELL (Look at the nesting growing to the right!):
// =====================================================================
placeOrder("Paneer Butter Masala", function(item) {
  processPayment(item, function(isPaid) {
    if (isPaid) {
      prepareFood(item, function(parcel) {
        deliverFood(parcel, function(finalStatus) {
          console.log("SUCCESS:", finalStatus);
        });
      });
    }
  });
});
```


--------------------------------------------------------------------------------
3.3 Why Callback Hell is Dangerous & Bad Practice
--------------------------------------------------------------------------------
1. UNREADABLE & UNMAINTAINABLE:
   Code moves from left-to-right rather than top-to-bottom. Debugging 10 nested
   levels in production will give any developer a headache.

2. NIGHTMARE ERROR HANDLING:
   If step 3 fails, where do you catch the error? You have to write `if (err)`
   checks inside every single layer of callbacks.

3. INVERSION OF CONTROL (CRITICAL CONCEPT):
   When you pass your callback function to a 3rd-party library function, you
   are giving up control. What if that 3rd-party library calls your callback
   TWICE? (e.g. charging a customer's credit card twice!).
   You lose control over WHEN and HOW OFTEN your callback is executed.

Visual Shape of Callback Hell:
--------------------------------------------------------------------------------
step1(function() {
    step2(function() {
        step3(function() {
            step4(function() {
                step5(function() {
                    // Looks like a pyramid / triangle! (Pyramid of Doom)
                });
            });
        });
    });
});
--------------------------------------------------------------------------------

How do we solve this?
JavaScript introduced PROMISES in ES6 (2015)!

4. TOPIC 3: THE SOLUTION — PROMISES
================================================================================

--------------------------------------------------------------------------------
4.1 What is a Promise?
--------------------------------------------------------------------------------
DEFINITION:
A Promise in JavaScript is an OBJECT representing the eventual completion
(fulfillment) or failure (rejection) of an asynchronous operation, and its
resulting value.

REAL-WORLD ANALOGY (The Restaurant Buzzer Token):
1. You go to Shake Shack / Burger King and order a burger.
2. The cashier doesn't give you the burger immediately because it takes 5 mins.
3. Instead, the cashier gives you an electronic BUZZER (A Promise).
4. While holding the buzzer:
   - You don't have the burger yet, but you have the GUARANTEE of getting it.
   - You can sit down, read messages, or talk to friends (non-blocking).
5. When the food is ready:
   - The buzzer BEEPS GREEN -> Order Fulfilled (Resolved)! You collect your food.
   - OR the manager says "Sorry, we ran out of buns!" -> Order Failed (Rejected).


--------------------------------------------------------------------------------
4.2 The Three States of a Promise
--------------------------------------------------------------------------------
A Promise is always in one of three states:

  1. PENDING:
     The initial state. The async task is still running (Burger is cooking).
     Neither resolved nor rejected yet.

  2. FULFILLED (Resolved):
     The operation completed successfully! A value is available.
     (Burger is ready, handed to you).

  3. REJECTED:
     The operation failed! An error reason is available.
     (Kitchen fire or out of stock).

IMPORTANT RULE:
A Promise can settle ONLY ONCE. Once it becomes Fulfilled or Rejected, its
state is IMMUTABLE (can never change back).


--------------------------------------------------------------------------------
4.3 How to Create a Promise (`new Promise(resolve, reject)`)
--------------------------------------------------------------------------------
Syntax:
```javascript
const myPromise = new Promise((resolve, reject) => {
  // Do your async work here (API call, timer, database query)

  if (/* success */ true) {
    resolve("Data or success message");
  } else {
    reject("Error reason or error object");
  }
});
```

Working Example:
```javascript
// Function that returns a Promise
function checkWeather(isCloudy) {
  return new Promise((resolve, reject) => {
    console.log("Checking weather report...");

    setTimeout(() => {
      if (!isCloudy) {
        resolve("Sun is shining! Great day for a picnic.");
      } else {
        reject("It's pouring rain! Picnic cancelled.");
      }
    }, 2000);
  });
}
```


--------------------------------------------------------------------------------
4.4 How to Consume a Promise (`.then()`, `.catch()`, `.finally()`)
--------------------------------------------------------------------------------
To read the result of a Promise, we attach three handler methods:

  1. `.then(value => { ... })`
     Runs when the promise is FULFILLED (resolve was called).
  2. `.catch(error => { ... })`
     Runs when the promise is REJECTED (reject was called or an error was thrown).
  3. `.finally(() => { ... })`
     Runs ALWAYS after the promise finishes, whether it succeeded or failed.
     (Perfect for hiding loaders/spinners).

Example Consuming `checkWeather`:
```javascript
checkWeather(false) // Try changing to true to see the catch block!
  .then((message) => {
    console.log("SUCCESS:", message);
  })
  .catch((error) => {
    console.log("ERROR:", error);
  })
  .finally(() => {
    console.log("Weather check complete. Loader stopped.");
  });

/*
Output (when isCloudy is false):
Checking weather report...
(2 seconds later)
SUCCESS: Sun is shining! Great day for a picnic.
Weather check complete. Loader stopped.
*/
```


--------------------------------------------------------------------------------
4.5 Promise Chaining: Eliminating Callback Hell!
--------------------------------------------------------------------------------
The superpower of Promises is CHAINING.
If you return a new Promise from inside a `.then()`, you can chain another
`.then()` below it.

This turns horizontal Callback Hell into clean, vertical, readable code!

Let's rewrite our Food Delivery example using Promise Chaining:

```javascript
function placeOrder(item) {
  return new Promise((resolve) => {
    setTimeout(() => {
      console.log("1. Order placed for:", item);
      resolve(item);
    }, 1000);
  });
}

function processPayment(item) {
  return new Promise((resolve) => {
    setTimeout(() => {
      console.log("2. Payment done for:", item);
      resolve(item);
    }, 1000);
  });
}

function prepareFood(item) {
  return new Promise((resolve) => {
    setTimeout(() => {
      console.log("3. Food prepared for:", item);
      resolve("Hot " + item + " Box");
    }, 1000);
  });
}

function deliverFood(box) {
  return new Promise((resolve) => {
    setTimeout(() => {
      console.log("4. Delivered:", box);
      resolve("Order Delivered Successfully!");
    }, 1000);
  });
}

// =====================================================================
// CLEAN PROMISE CHAIN (Flat, top-to-bottom, ONE central catch!):
// =====================================================================
placeOrder("Margherita Pizza")
  .then((item) => {
    return processPayment(item);
  })
  .then((item) => {
    return prepareFood(item);
  })
  .then((box) => {
    return deliverFood(box);
  })
  .then((status) => {
    console.log("ALL DONE:", status);
  })
  .catch((err) => {
    // If ANY step above fails, execution jumps straight here!
    console.error("Oops! Something went wrong:", err);
  });
```

Shortcut: With Arrow functions, if you only return, you can write:
```javascript
placeOrder("Margherita Pizza")
  .then(item => processPayment(item))
  .then(item => prepareFood(item))
  .then(box  => deliverFood(box))
  .then(status => console.log(status))
  .catch(err => console.error(err));
```
Look how clean and readable that is compared to Callback Hell!

4.6 Comprehensive Guide to All Promise Methods
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
4.6.1 The Two Categories: Instance Methods vs Static Methods
--------------------------------------------------------------------------------
In JavaScript, Promise methods are divided into TWO distinct families:

1. INSTANCE METHODS (Called on an existing Promise object):
   - `.then(onFulfilled, onRejected)`
   - `.catch(onRejected)`
   - `.finally(onFinally)`
   These methods are attached to a specific promise instance to handle its
   outcome or perform cleanup.

2. STATIC METHODS (Called directly on the `Promise` constructor class):
   A. The 4 Combinators (Running multiple promises together):
      - `Promise.all([p1, p2, ...])`
      - `Promise.allSettled([p1, p2, ...])`
      - `Promise.race([p1, p2, ...])`
      - `Promise.any([p1, p2, ...])`

   B. The 2 Instant Creation Utilities:
      - `Promise.resolve(value)`
      - `Promise.reject(reason)`

   C. The Modern ES2024 Addition:
      - `Promise.withResolvers()`


--------------------------------------------------------------------------------
4.6.2 Deep Dive into Instance Methods (`.then`, `.catch`, `.finally`)
--------------------------------------------------------------------------------
Every Promise object inherits three core methods from `Promise.prototype`:

1. `.then(onFulfilled, onRejected)`:
   - Takes up to TWO callback arguments:
     * `onFulfilled`: Runs if the promise resolves successfully. Receives value.
     * `onRejected`: (Optional) Runs if the promise rejects. Receives error.
   - ALWAYS returns a NEW Promise, allowing chaining.
   - Whatever you return from `.then()` gets wrapped into the next Promise!

   ```javascript
   fetchUser()
     .then(
       (user) => { console.log("User:", user); },
       (err)  => { console.error("Optional direct error handler:", err); }
     );
   ```

2. `.catch(onRejected)`:
   - Syntactic sugar for `.then(null, onRejected)`.
   - Catches ANY error or rejection that occurred anywhere up the chain!
   - You can also "recover" from an error by returning a fallback value:

   ```javascript
   fetchCachedData()
     .catch((err) => {
       console.warn("Cache missed, using default fallback data.");
       return { role: "guest", permissions: [] }; // Recovery value!
     })
     .then((data) => {
       console.log("Current user data:", data); // Runs with the fallback!
     });
   ```

3. `.finally(onFinally)`:
   - Takes ONE callback with NO arguments (`() => { ... }`).
   - Runs GUARANTEED when the promise settles (whether resolved OR rejected).
   - Ideal for teardown: hiding loading spinners, closing database connections,
     resetting forms, or clearing timeouts.
   - Unlike `.then()`, `.finally()` does not modify the resolved value or error;
     it quietly passes the original outcome down to the next step.

   ```javascript
   showSpinner(true);

   fetchData()
     .then(data => renderUI(data))
     .catch(err => showErrorAlert(err.message))
     .finally(() => {
       showSpinner(false); // ALWAYS runs, win or lose!
       console.log("Operation finished.");
     });
   ```


--------------------------------------------------------------------------------
4.6.3 Quick Comparison Matrix of Static Combinators
--------------------------------------------------------------------------------
When you have an array/iterable of promises, which static method should you use?

+--------------------+-----------------------------+-----------------------------+-------------------------------------+
| Method             | Resolves When...            | Rejects When...             | Best Real-World Use Case            |
+--------------------+-----------------------------+-----------------------------+-------------------------------------+
| Promise.all()      | ALL promises resolve        | ANY single promise rejects  | Dependent operations (Dashboard:    |
|                    | (returns array of values)   | (fails fast on first error) | User + Orders + Settings together)  |
+--------------------+-----------------------------+-----------------------------+-------------------------------------+
| Promise.allSettled()| ALL promises settle        | NEVER rejects!              | Bulk operations where partial       |
|                    | (success or fail)           | (always fulfills with       | success is acceptable               |
|                    |                             | status array)               | (e.g. sending 1,000 push emails)    |
+--------------------+-----------------------------+-----------------------------+-------------------------------------+
| Promise.race()     | ANY promise settles FIRST   | ANY promise settles FIRST   | Request timeouts (race API call     |
|                    | (resolves if winner resolves)| (rejects if winner rejects)| against a 5-second cancel timer)    |
+--------------------+-----------------------------+-----------------------------+-------------------------------------+
| Promise.any()      | ANY promise resolves FIRST  | ALL promises reject         | Fastest mirror / CDN download       |
|                    | (first success wins)        | (throws AggregateError)     | (try Server A, B, C; pick 1st ok)   |
+--------------------+-----------------------------+-----------------------------+-------------------------------------+


--------------------------------------------------------------------------------
4.6.4 `Promise.all()` — "All or Nothing" (Fail-Fast Parallelism)
--------------------------------------------------------------------------------
Analogy: Four friends booking plane tickets together.
- If all 4 seats are confirmed -> The trip is ON!
- If even 1 friend gets rejected -> The ENTIRE group trip is CANCELLED immediately!

Characteristics:
- Takes an array of promises.
- Runs them in PARALLEL (simultaneously).
- Resolves when ALL promises resolve, returning an array of results in the
  EXACT same order as the input array.
- FAILS FAST: As soon as ANY single promise rejects, `Promise.all` immediately
  rejects with that error, ignoring all other pending promises.

Working Example (Success Scenario):
```javascript
const fetchProfile = new Promise((resolve) => {
  setTimeout(() => resolve({ name: "Aarav", role: "Admin" }), 1000);
});

const fetchNotifications = new Promise((resolve) => {
  setTimeout(() => resolve(["Welcome back!", "System update at 10 PM"]), 1500);
});

const fetchSettings = new Promise((resolve) => {
  setTimeout(() => resolve({ theme: "dark", lang: "en" }), 500);
});

console.time("Promise.all Timer");

Promise.all([fetchProfile, fetchNotifications, fetchSettings])
  .then(([profile, notifications, settings]) => {
    console.timeEnd("Promise.all Timer"); // ~1500ms (not 1000 + 1500 + 500 = 3000ms!)
    console.log("Profile:", profile.name);
    console.log("Notifications count:", notifications.length);
    console.log("Theme:", settings.theme);
  })
  .catch((err) => {
    console.error("Failed to load dashboard:", err);
  });
```

Working Example (Fail-Fast Scenario):
```javascript
const task1 = Promise.resolve("Task 1 finished");
const task2 = new Promise((_, reject) => setTimeout(() => reject("Network Failed!"), 800));
const task3 = new Promise((resolve) => setTimeout(() => resolve("Task 3 finished"), 2000));

Promise.all([task1, task2, task3])
  .then(results => console.log("All success:", results))
  .catch(err => console.error("Promise.all rejected early with:", err));

// Output after ~800ms:
// Promise.all rejected early with: Network Failed!
// (Task 3 was still running, but the entire batch was already aborted!)
```


--------------------------------------------------------------------------------
4.6.5 `Promise.allSettled()` — "Wait for Everybody" (Safe & Resilient)
--------------------------------------------------------------------------------
Introduced in ES2020 (ES11).

Analogy: A teacher collecting exam sheets from 30 students.
The teacher waits until EVERY student submits their paper. Some passed, some
failed, but the teacher records every single student's status without throwing
away the whole class!

Characteristics:
- Takes an array of promises.
- WAITS FOR ALL PROMISES TO SETTLE (either fulfilled or rejected).
- NEVER rejects! The outer promise will ALWAYS fulfill successfully.
- Returns an array of objects, where each object has:
  * For fulfilled: `{ status: "fulfilled", value: <result> }`
  * For rejected:  `{ status: "rejected",  reason: <error> }`

Working Example (Bulk Operations):
```javascript
const serviceA = Promise.resolve("Service A: Healthy");
const serviceB = Promise.reject(new Error("Service B: Database Down"));
const serviceC = Promise.resolve("Service C: Healthy");

Promise.allSettled([serviceA, serviceB, serviceC])
  .then((results) => {
    console.log("Health Check Summary:");
    results.forEach((res, index) => {
      if (res.status === "fulfilled") {
        console.log(`- Service ${index + 1}: SUCCESS -> ${res.value}`);
      } else {
        console.log(`- Service ${index + 1}: FAILED  -> ${res.reason.message}`);
      }
    });

    // Easily filter only successful ones:
    const successful = results
      .filter(r => r.status === "fulfilled")
      .map(r => r.value);
    console.log("Ready services:", successful);
  });

/*
Output:
Health Check Summary:
- Service 1: SUCCESS -> Service A: Healthy
- Service 2: FAILED  -> Service B: Database Down
- Service 3: SUCCESS -> Service C: Healthy
Ready services: [ 'Service A: Healthy', 'Service C: Healthy' ]
*/
```


--------------------------------------------------------------------------------
4.6.6 `Promise.race()` — "First to Settle" (Speed / Timeouts)
--------------------------------------------------------------------------------
Analogy: An Olympic 100m sprint race.
Whoever crosses the finish line FIRST wins the gold medal. It doesn't matter
if the first person successfully crosses or trips and falls over the finish line;
as soon as someone crosses, the race is over!

Characteristics:
- Takes an array of promises.
- Returns the outcome of the FIRST promise that settles (whether it RESOLVES
  or REJECTS).
- If the fastest promise resolves -> `Promise.race` resolves.
- If the fastest promise rejects  -> `Promise.race` rejects.

Working Example (Creating a Network Request Timeout):
```javascript
// Simulate a slow network request (takes 5 seconds)
function slowFetchData() {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Downloaded 100MB of Data!"), 5000);
  });
}

// Timeout promise that rejects after 2 seconds
function timeoutGuard(ms) {
  return new Promise((_, reject) => {
    setTimeout(() => reject(new Error(`Request timed out after ${ms}ms!`)), ms);
  });
}

// Race the data fetch against our 2-second timeout:
Promise.race([slowFetchData(), timeoutGuard(2000)])
  .then(data => console.log("Success:", data))
  .catch(err => console.error("Race Error:", err.message));

// Output after 2000ms:
// Race Error: Request timed out after 2000ms!
```


--------------------------------------------------------------------------------
4.6.7 `Promise.any()` — "First to Succeed" (Redundancy / Fallback)
--------------------------------------------------------------------------------
Introduced in ES2021 (ES12).

Analogy: Calling 3 emergency taxi drivers.
You only need ONE taxi to take you to the airport.
- Driver 1 says "No, car broken" (rejected). You don't give up!
- Driver 2 says "Yes, I'm outside!" (resolved). YOU TAKE THIS ONE AND LEAVE!
- Only if ALL 3 drivers say "No" do you have a total failure.

Characteristics:
- Takes an array of promises.
- Returns the value of the FIRST promise that FULFILLS (resolves successfully).
- IGNORES REJECTIONS as long as at least one promise can still succeed!
- Only rejects if ALL promises reject. In that case, it throws an `AggregateError`
  (a special error containing an `.errors` array with all reasons).

Difference between `Promise.race()` and `Promise.any()`:
- `Promise.race()`: First to FINISH (success OR failure).
- `Promise.any()`:  First to SUCCEED (ignores failures until all fail).

Working Example (Redundant CDN Mirrors):
```javascript
const cdnMirrorUS = new Promise((_, reject) => {
  setTimeout(() => reject("US CDN 503 Server Error"), 400); // Fails fast
});

const cdnMirrorEU = new Promise((resolve) => {
  setTimeout(() => resolve("Asset loaded from EU Server!"), 900); // Slower, but works!
});

const cdnMirrorAsia = new Promise((resolve) => {
  setTimeout(() => resolve("Asset loaded from Asia Server!"), 1200);
});

Promise.any([cdnMirrorUS, cdnMirrorEU, cdnMirrorAsia])
  .then((winner) => {
    console.log("Success:", winner);
  })
  .catch((err) => {
    console.error("All CDNs failed:", err.errors);
  });

// Output after 900ms:
// Success: Asset loaded from EU Server!
// (Notice: US failed at 400ms, but Promise.any ignored it and waited for EU!)
```

Working Example (When All Reject):
```javascript
const p1 = Promise.reject("Fail 1");
const p2 = Promise.reject("Fail 2");

Promise.any([p1, p2])
  .catch((err) => {
    console.log(err.name);    // "AggregateError"
    console.log(err.message); // "All promises were rejected"
    console.log(err.errors);  // ["Fail 1", "Fail 2"]
  });
```


--------------------------------------------------------------------------------
4.6.8 `Promise.resolve()` & `Promise.reject()` — Instant Settled Promises
--------------------------------------------------------------------------------
Sometimes you already have data or a known error immediately and want to return
a Promise without writing verbose `new Promise((resolve) => resolve(...))` syntax.

1. `Promise.resolve(value)`:
   Returns a Promise object that is already resolved with the given value.

   ```javascript
   // Cache lookup utility
   const cache = { user_42: { name: "Neha Sharma", role: "Manager" } };

   function getUser(id) {
     if (cache[id]) {
       // Return cached data immediately as a Promise:
       return Promise.resolve(cache[id]);
     }
     // Otherwise fetch from database (async):
     return fetch(`/api/users/${id}`).then(res => res.json());
   }

   // Consumed identically either way!
   getUser("user_42").then(user => console.log("Cached User:", user.name));
   ```

2. `Promise.reject(reason)`:
   Returns a Promise object that is already rejected with the given reason.

   ```javascript
   function validateAge(age) {
     if (age < 18) {
       // Immediate rejection without running any timers or async work:
       return Promise.reject(new Error("Access Denied: Must be 18 or older."));
     }
     return Promise.resolve("Access Granted!");
   }

   validateAge(15)
     .then(msg => console.log(msg))
     .catch(err => console.error("Validation Error:", err.message));
   ```


--------------------------------------------------------------------------------
4.6.9 Modern Addition: `Promise.withResolvers()` (ES2024 Standard)
--------------------------------------------------------------------------------
Added to JavaScript in ES2024 (Node.js 22+, modern Chrome, Firefox, Safari).

THE PROBLEM IT SOLVES:
Historically, if you needed to resolve or reject a promise from OUTSIDE its
constructor callback (for example, inside an event listener or a socket callback),
you had to do this ugly "deferred" trick:

```javascript
// THE OLD, CLUNKY WAY:
let resolveFn, rejectFn;
const myOldPromise = new Promise((resolve, reject) => {
  resolveFn = resolve;
  rejectFn = reject;
});
// Now you could call resolveFn() from outside. Awkward!
```

THE MODERN ES2024 WAY:
`Promise.withResolvers()` returns a plain object containing:
- `promise`: The Promise instance.
- `resolve`: The resolve function.
- `reject`: The reject function.

```javascript
const { promise, resolve, reject } = Promise.withResolvers();

// Example: Trigger promise resolution when user clicks a button
document.getElementById("submitBtn")?.addEventListener("click", () => {
  resolve("User clicked submit!");
});

// Elsewhere in your code:
promise.then(msg => console.log(msg));
```


--------------------------------------------------------------------------------
4.7 Decision Guide: Which Promise Method Should You Use?
--------------------------------------------------------------------------------
Ask yourself these simple questions:

  Do you have MULTIPLE promises running concurrently?
  │
  ├── Do you need ALL of them to succeed?
  │   └── YES, and if any fails, abort immediately:
  │       👉 Use `Promise.all()`
  │
  ├── Do you want to wait for ALL of them, even if some fail?
  │   └── YES, I need a complete status report for every single one:
  │       👉 Use `Promise.allSettled()`
  │
  ├── Do you need only the FASTEST response, win or lose?
  │   └── YES, first settled promise wins (e.g. timeout watchdog):
  │       👉 Use `Promise.race()`
  │
  └── Do you need only the FASTEST SUCCESSFUL response?
      └── YES, ignore individual errors until at least one succeeds:
          👉 Use `Promise.any()`

  Do you need to create a Promise INSTANTLY with an existing value/error?
  ├── Already have a successful value? 👉 Use `Promise.resolve(value)`
  └── Already have an error condition? 👉 Use `Promise.reject(reason)`

5. TOPIC 4: THE ULTIMATE MODERN SYNTAX — ASYNC / AWAIT
================================================================================

--------------------------------------------------------------------------------
5.1 What is Async / Await?
--------------------------------------------------------------------------------
DEFINITION:
`async` and `await` are keywords introduced in ES2017 (ES8).
They are "Syntactic Sugar" built ON TOP OF Promises.
"Syntactic Sugar" means it doesn't do anything fundamentally new under the hood,
but it makes the syntax much sweeter, cleaner, and look like normal SYNCHRONOUS
code while remaining 100% NON-BLOCKING!

GOLDEN RULES:
1. The `async` keyword can be placed before ANY function declaration.
2. The `await` keyword can ONLY be used INSIDE an `async` function.
3. `await` pauses the execution of the function until the Promise settles.
   (It does NOT freeze the browser! Other scripts and UI continue smoothly).


--------------------------------------------------------------------------------
5.2 The `async` Keyword
--------------------------------------------------------------------------------
Putting `async` in front of a function does one magical thing:
IT AUTOMATICALLY WRAPS THE RETURN VALUE IN A PROMISE!

```javascript
// Normal function
function getNumber() {
  return 42;
}

// Async function
async function getAsyncNumber() {
  return 42;
}

console.log(getNumber());      // Output: 42
console.log(getAsyncNumber()); // Output: Promise { 42 }

// Consuming it:
getAsyncNumber().then(val => console.log("Value is:", val)); // Value is: 42
```


--------------------------------------------------------------------------------
5.3 The `await` Keyword
--------------------------------------------------------------------------------
`await` literally tells JavaScript:
"Wait here for this Promise to finish and give me its resolved value, before
moving to the next line."

Compare Promise vs Async/Await:

Using `.then()`:
```javascript
fetchData().then(data => {
  console.log(data);
});
```

Using `await`:
```javascript
const data = await fetchData();
console.log(data);
```
No callbacks, no `.then()` chains! It looks just like normal linear code!


--------------------------------------------------------------------------------
5.4 Error Handling with `try...catch...finally`
--------------------------------------------------------------------------------
With Promises, we used `.catch()`.
With `async/await`, we use standard JavaScript `try...catch` blocks!

```javascript
function fetchStudentData(studentId) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (studentId > 0) {
        resolve({ id: studentId, name: "Sneha Patel", marks: 92 });
      } else {
        reject(new Error("Invalid Student ID!"));
      }
    }, 1500);
  });
}

async function showStudentReport(id) {
  try {
    console.log("Loading student details...");
    // Await pauses inside this function until the promise finishes
    const student = await fetchStudentData(id);

    console.log("Student Name:", student.name);
    console.log("Marks:", student.marks);
  } catch (error) {
    // If the promise rejects, execution jumps straight here!
    console.error("Error occurred:", error.message);
  } finally {
    // Always runs
    console.log("Process complete. Spinner hidden.");
  }
}

// Test with valid ID:
showStudentReport(10);
// Test with invalid ID:
showStudentReport(-1);
```


--------------------------------------------------------------------------------
5.5 Converting the Food Delivery Workflow to Async/Await
--------------------------------------------------------------------------------
Remember the 4-step food order? Look at how gorgeous and readable it is now:

```javascript
async function executeOrder() {
  try {
    console.log("--- Starting Order Process ---");

    const item = await placeOrder("Paneer Tikka Roll");
    const paidItem = await processPayment(item);
    const parcel = await prepareFood(paidItem);
    const finalReceipt = await deliverFood(parcel);

    console.log("SUCCESS:", finalReceipt);
  } catch (err) {
    console.error("Order Failed:", err);
  } finally {
    console.log("Thank you for choosing our service!");
  }
}

executeOrder();
```
Look at that! It reads like a simple shopping list:
1. Place order.
2. Pay.
3. Prepare.
4. Deliver.
Zero nesting, zero pyramid of doom, crystal clear!

6. THE GRAND EVOLUTION: SAME PROBLEM SOLVED 3 WAYS
================================================================================
Let's see the direct visual comparison of doing 3 dependent async steps:
Step 1: Authenticate User
Step 2: Fetch User Profile
Step 3: Fetch User Posts

--------------------------------------------------------------------------------
6.1 WAY 1: The Callback Way (Old, Nested, Messy)
--------------------------------------------------------------------------------
```javascript
loginUser("admin@example.com", "12345", function(user, err) {
  if (err) {
    console.error("Login failed");
  } else {
    getUserProfile(user.id, function(profile, err) {
      if (err) {
        console.error("Profile failed");
      } else {
        getUserPosts(profile.id, function(posts, err) {
          if (err) {
            console.error("Posts failed");
          } else {
            console.log("Posts:", posts);
          }
        });
      }
    });
  }
});
```
Problems: Deep nesting, repetitive error handling, painful to modify.

--------------------------------------------------------------------------------
6.2 WAY 2: The Promise Way (ES6 - 2015, Much Better)
--------------------------------------------------------------------------------
```javascript
loginUser("admin@example.com", "12345")
  .then(user => getUserProfile(user.id))
  .then(profile => getUserPosts(profile.id))
  .then(posts => {
    console.log("Posts:", posts);
  })
  .catch(err => {
    console.error("Something failed:", err);
  });
```
Improvements: Flat structure, single `.catch()` handles any error along the way.

--------------------------------------------------------------------------------
6.3 WAY 3: The Async/Await Way (Modern Standard, Best & Cleanest)
--------------------------------------------------------------------------------
```javascript
async function loadDashboard() {
  try {
    const user = await loginUser("admin@example.com", "12345");
    const profile = await getUserProfile(user.id);
    const posts = await getUserPosts(profile.id);

    console.log("Posts:", posts);
  } catch (err) {
    console.error("Something failed:", err);
  }
}

loadDashboard();
```
Improvements: Reads completely synchronously, easy to debug with standard
try/catch, matches how human brains think.

7. COMMON MISTAKES, TIPS & BEST PRACTICES
================================================================================

1. MISTAKE: Forgetting `return` in a Promise Chain
   WRONG:
   ```javascript
   getUser()
     .then(user => {
       fetchPosts(user.id); // Forgot return! Next .then receives undefined!
     })
     .then(posts => {
       console.log(posts); // undefined!
     });
   ```
   CORRECT:
   ```javascript
   getUser()
     .then(user => {
       return fetchPosts(user.id); // Explicit return
     })
     .then(posts => console.log(posts));
   ```

2. MISTAKE: Forgetting `await`
   ```javascript
   async function test() {
     const data = fetchData(); // Forgot await!
     console.log(data); // Prints: Promise { <pending> } instead of actual data!
   }
   ```
   Always remember: If a function returns a Promise, use `await` to unwrap it.

3. MISTAKE: Using `await` sequentially when tasks are INDEPENDENT
   If two API calls do NOT depend on each other, do NOT await them one by one:
   SLOW (Takes 2s + 2s = 4s total):
   ```javascript
   const users = await fetchUsers();     // takes 2s
   const products = await fetchProducts(); // takes 2s
   ```
   FAST (Takes only 2s total using Promise.all):
   ```javascript
   const [users, products] = await Promise.all([fetchUsers(), fetchProducts()]);
   ```

4. MISTAKE: Using `await` inside a normal function without `async`
   ```javascript
   function doSomething() {
     const res = await fetch("api/data"); // SyntaxError: await is only valid in async functions
   }
   ```
   Fix: Add `async` to the function: `async function doSomething() { ... }`

8. RAPID-FIRE INTERVIEW QUESTIONS & QUICK ANSWERS
================================================================================

Q1: Is JavaScript single-threaded or multi-threaded?
A1: JavaScript is single-threaded. It has one call stack and executes one command
    at a time. It handles asynchronous operations using the browser's Web APIs,
    Task Queue, and the Event Loop.

Q2: What is the difference between a Callback and a Promise?
A2: - A Callback is a function passed to another function to be executed later.
      Nesting callbacks leads to Callback Hell and Inversion of Control.
    - A Promise is an object that guarantees a future value (Pending, Fulfilled,
      Rejected) with built-in chaining (`.then`, `.catch`), avoiding Callback Hell.

Q3: What are the three states of a Promise?
A3: 1. Pending (working, initial state)
    2. Fulfilled (resolved successfully with a value)
    3. Rejected (failed with an error reason)

Q4: What is the difference between `.then()` chaining and `async/await`?
A4: Both do the exact same thing under the hood. However:
    - `.then()` uses promise callback chains.
    - `async/await` provides cleaner, synchronous-like syntax without `.then()`
      callbacks and uses standard `try...catch` blocks for error handling.

Q5: Can `await` be used without `async`?
A5: In standard function scopes, NO. An `await` can only be used inside an `async`
    function. (Exception: Top-level `await` is allowed in modern ES modules).

Q6: What happens if you don't catch an error in a Promise?
A6: The browser or Node.js environment will trigger an
    `UnhandledPromiseRejection` warning or error, which can cause apps to crash.
    Always use `.catch()` or a `try...catch` block.

Q7: What are the main differences between `Promise.all`, `Promise.allSettled`, `Promise.race`, and `Promise.any`?
A7: - `Promise.all`: Waits for all to fulfill. Fails fast if any rejects.
    - `Promise.allSettled`: Waits for all to settle (fulfilled or rejected). Never rejects.
    - `Promise.race`: Returns the first promise to settle (whether fulfilled OR rejected).
    - `Promise.any`: Returns the first promise to fulfill. Rejects only if ALL reject (AggregateError).

Q8: What is the benefit of `Promise.resolve(value)` over `new Promise(res => res(value))`?
A8: `Promise.resolve()` is much cleaner, more concise, and faster to write. It also
    safely unwraps any existing Promise or "thenable" passed into it, returning
    the underlying promise directly.

Q9: What is `Promise.withResolvers()` introduced in ES2024?
A9: It is a static method that returns `{ promise, resolve, reject }`, allowing you
    to resolve or reject a promise from outside its executor function without
    having to define external closure variables.
