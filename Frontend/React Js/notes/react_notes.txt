                    REACT JS - QUICK REVISION NOTES (CONCISE)
================================================================================

1. WHAT IS REACT?
--------------------------------------------------------------------------------
- Definition: An open-source, front-end JavaScript library used to build fast, 
  interactive User Interfaces (UIs), especially Single-Page Applications (SPAs).
- Creator: Jordan Walke (Meta / Facebook) in 2013.
- Core Identity: It is a library, NOT a full framework. It handles only the "View" 
  layer in MVC architecture.


2. KEY FEATURES
--------------------------------------------------------------------------------
1. Virtual DOM (VDOM):
   - An in-memory lightweight copy of the real DOM.
   - Compares changes using a "Diffing" algorithm and updates ONLY the modified 
     elements in the real DOM (Reconciliation) for high performance.
2. Component-Based Architecture:
   - UI is split into small, reusable, independent pieces called Components.
3. One-Way Data Binding:
   - Data flows unidirectionally from Parent to Child via `props`.
4. Declarative UI:
   - You describe WHAT the UI should look like for a given state; React handles 
     DOM updates automatically.


3. NODE_MODULES & PACKAGE MANAGEMENT
--------------------------------------------------------------------------------
- node_modules/:
  * Contains all installed third-party libraries and dependencies.
  * Very large folder; NEVER edit it manually; ALWAYS add to `.gitignore`.
  * Can be re-created anytime by running: `npm install`.
- package.json:
  * Project manifest holding project metadata, scripts (`dev`, `build`), and 
    package dependencies (`react`, `vite`, etc.).
- package-lock.json:
  * Records the exact versions of every installed package to ensure identical 
    setups across different computers.


4. REACT PROJECT STRUCTURE (Vite Setup)
--------------------------------------------------------------------------------
my-app/
├── node_modules/             # Installed dependencies
├── public/                   # Static assets (favicon, etc.)
├── src/                      # Application source code
│   ├── assets/               # Images and media files
│   ├── App.jsx               # Root parent component
│   ├── App.css               # Styling for App component
│   ├── index.css             # Global styles
│   └── main.jsx              # Entry file: mounts React app to the HTML DOM
├── index.html                # Single HTML page holding `<div id="root"></div>`
├── package.json              # Project dependencies and run scripts
└── vite.config.js            # Vite build configuration

* How It Connects:
  `index.html` (<div id="root">) <== `main.jsx` (createRoot) <== `<App />` (src/App.jsx)


5. BABEL COMPILER
--------------------------------------------------------------------------------
- Definition: A JavaScript compiler / transpiler.
- Purpose:
  1. Compiles JSX into standard browser-readable JavaScript (`React.createElement`).
  2. Transpiles modern ES6+ JavaScript into backward-compatible ES5 for older browsers.
- Example:
  // Written in JSX:
  const el = <h1>Hello</h1>;

  // Babel compiles to:
  const el = React.createElement('h1', null, 'Hello');


6. JSX & CORE JSX RULES
--------------------------------------------------------------------------------
- Definition: JSX (JavaScript XML) is a syntax extension that lets you write 
  HTML-like code inside JavaScript.

- 5 Essential Rules:
  1. Single Parent Element: Must return one wrapper tag or Fragment (`<>...</>`).
     * Correct:   return <div><h1>Hi</h1><p>Text</p></div>;
     * Incorrect: return <h1>Hi</h1><p>Text</p>; // Error!

  2. Close All Tags: Self-closing tags MUST have a slash:
     * `<img src="pic.jpg" alt="" />`, `<input type="text" />`, `<br />`

  3. camelCase Attributes:
     * `class`    ==> `className`
     * `for`      ==> `htmlFor`
     * `onclick`  ==> `onClick`
     * `onchange` ==> `onChange`

  4. JavaScript in JSX uses `{}`:
     * `const name = "Alex"; return <h1>Hello, {name}</h1>;`

  5. Inline Styles as Objects:
     * `<div style={{ color: "red", fontSize: "18px" }}>Styled</div>`


7. REACT FRAGMENT
--------------------------------------------------------------------------------
- Definition: A built-in wrapper component used to group multiple elements 
  without adding an extra node/`<div>` to the real DOM.
- Why Use: Prevents unnecessary `<div>` nesting ("div soup") and preserves 
  CSS Flexbox/Grid layouts.
- Syntax:
  * Shorthand (Preferred):
      <>
        <h1>Title</h1>
        <p>Description</p>
      </>
  * Explicit (Required only when passing a `key` prop):
      <React.Fragment key={item.id}>
        <h1>{item.title}</h1>
      </React.Fragment>


8. REACT STRICT MODE (<React.StrictMode>)
--------------------------------------------------------------------------------
- Definition: A development-only helper component that checks for common bugs 
  and deprecated features.
- Key Behaviors:
  * Has NO visual UI in the DOM.
  * Has ZERO effect on the production build.
  * Deliberately renders components TWICE in development to detect accidental 
    side effects and uncleaned subscriptions.


9. APPLICATION EXECUTION FLOW
--------------------------------------------------------------------------------
1. Browser requests and loads `index.html`.
2. `index.html` loads `<script type="module" src="/src/main.jsx">`.
3. `main.jsx` selects `<div id="root">` via `document.getElementById('root')`.
4. `ReactDOM.createRoot()` mounts the root `<App />` component inside `#root`.
5. `<App />` renders JSX -> React Virtual DOM injects final HTML into the page.


10. REACT COMPONENTS & TYPES
--------------------------------------------------------------------------------
- Component Definition: Self-contained, reusable UI blocks that return JSX.
- Rule: Component names MUST start with a Capital Letter (PascalCase), e.g., `Header`, `Card`.

- Definitions of the Two Types:
  1. Functional Component:
     * A plain JavaScript function (regular or arrow function) that accepts `props` 
       as an argument and returns JSX.
     * Manages state and lifecycle features cleanly using React Hooks (`useState`, `useEffect`).
  2. Class-Based Component:
     * An ES6 JavaScript class that extends `React.Component` and contains a mandatory 
       `render()` method returning JSX.
     * Manages state via `this.state` object and lifecycle via explicit lifecycle methods.


11. FUNCTIONAL VS CLASS COMPONENTS (WITH EXAMPLES)
--------------------------------------------------------------------------------

a) Functional Component (Modern - Concise & Hook-based):
   -----------------------------------------------------
   import React, { useState } from 'react';

   function Counter() {
     const [count, setCount] = useState(0);

     return (
       <div>
         <p>Count: {count}</p>
         <button onClick={() => setCount(count + 1)}>Increment</button>
       </div>
     );
   }
   export default Counter;

b) Class-Based Component (Legacy - Verbose & Boilerplate-heavy):
   ------------------------------------------------------------
   import React, { Component } from 'react';

   class Counter extends Component {
     constructor(props) {
       super(props);
       this.state = { count: 0 };
       this.handleIncrement = this.handleIncrement.bind(this);
     }

     handleIncrement() {
       this.setState({ count: this.state.count + 1 });
     }

     render() {
       return (
         <div>
           <p>Count: {this.state.count}</p>
           <button onClick={this.handleIncrement}>Increment</button>
         </div>
       );
     }
   }
   export default Counter;


12. WHY ARE CLASS COMPONENTS LEGACY / LESS PREFERRED?
--------------------------------------------------------------------------------
1. Tricky `this` Keyword: Requires manual method binding (`.bind(this)`); easy 
   to cause runtime `undefined` bugs.
2. Heavy Boilerplate: Needs `constructor`, `super(props)`, and explicit `render()` methods.
3. Fragmented Lifecycle: A single feature's logic had to be split across 
   `componentDidMount`, `componentDidUpdate`, and `componentWillUnmount`.
4. Hard to Share Logic: Required complex HOCs/Render Props ("wrapper hell").
5. React Roadmap: Meta placed class components in maintenance mode; all modern 
   features (Hooks, Server Components, Suspense) require functional components.


13. COMPARISON TABLE: FUNCTIONAL VS CLASS COMPONENTS
--------------------------------------------------------------------------------
+--------------------+--------------------------------+--------------------------------+
| Feature            | Functional Components (Modern) | Class Components (Legacy)      |
+--------------------+--------------------------------+--------------------------------+
| Syntax             | Plain JavaScript function      | ES6 class (extends Component)  |
| Boilerplate        | Minimal and clean              | Heavy and verbose              |
| 'this' Keyword     | Not needed                     | Required (this.state, props)   |
| State Handling     | `useState()` Hook              | `this.state` & `setState()`    |

| Performance / Size | Smaller bundle, easy to minify | Larger bundle, hard to minify  |
| Current Status     | Industry standard (100% active)| Legacy / Maintenance mode      |
+--------------------+--------------------------------+--------------------------------+

--------------------------------------------------------------------------------

+------------+---------------------------+-----------------------------------+---------------------------------------------+

+------------+---------------------------+-----------------------------------+---------------------------------------------+

* Key Takeaway:
  In Class components, lifecycle logic was split into 3-4 separate methods.
  In Functional components, `useEffect()` unifies Mounting, Updating, and Unmounting 
  into a single, clean hook.


15. ADVANTAGES OF FUNCTIONAL COMPONENTS
--------------------------------------------------------------------------------
1. Simple & Readable: Less code, straightforward JavaScript functions.
2. No `this` Binding: Eliminates one of JavaScript's most common sources of bugs.
3. React Hooks Support: Full state, side effects, and context access via built-in hooks.
4. Custom Hooks: Easy extraction and reuse of stateful logic without changing UI hierarchy.
5. Unified Side Effects: `useEffect` combines setup and cleanup in one concise spot.
6. Better Optimization: Minifiers and bundlers (Vite/Rollup) can compress functions 
   much better than ES6 classes, yielding faster page loads.
7. Future-Proof: The official standard for all modern React development.


16. IMPORT & EXPORT IN REACT (ES6 MODULES)
--------------------------------------------------------------------------------
a) Definitions:
   - export: Makes variables, functions, or components accessible to other files.
   - import: Pulls exported code from an external file into the current file.

b) Two Types of Exports & Imports:

   1. Default Export & Import:
      - Export: Only ONE default export is allowed per file.
      - Import: NO curly braces `{}`. You can choose ANY name when importing.
      * Export Example:
          function Navbar() { return <nav>Navbar</nav>; }
          export default Navbar;
      * Import Example (Can rename freely):
          import Navbar from './Navbar';
          import CustomNav from './Navbar'; // Also valid! Any name works.

   2. Named Export & Import:
      - Export: MULTIPLE named exports are allowed in a single file.
      - Import: MUST use curly braces `{}` and the EXACT exported name.
      * Export Example:
          export const Button = () => <button>Click</button>;
          export const Input = () => <input type="text" />;
      * Import Example (Exact name inside `{}`):
          import { Button, Input } from './FormElements';
      * Renaming via 'as' Keyword (Aliasing):
          import { Button as SubmitBtn } from './FormElements';

c) Combined Import (Default + Named):
   - You can import both in a single line.
   * Example:
       import React, { useState, useEffect } from 'react';
       // 'React'                ==> Default Import (no braces, custom name allowed)
       // '{ useState, useEffect }'==> Named Imports (inside braces, exact names)

d) Summary Table:
+--------------------+--------------------------------+--------------------------------+
| Criteria           | Default Export                 | Named Export                   |
+--------------------+--------------------------------+--------------------------------+
| Limit per file     | Only 1 per file                | Multiple per file              |
| Export Syntax      | export default Component;      | export const Item = ...;       |
| Import Syntax      | import Name from './file';     | import { Name } from './file'; |
| Curly Braces `{}`  | NO curly braces                | MUST use curly braces `{}`     |
| Naming on Import   | Any name allowed               | Must match exact exported name |
| Renaming           | Direct (rename freely)         | Requires `as` (`{ Name as New }`)
+--------------------+--------------------------------+--------------------------------+


17. PROPS IN REACT (PROPERTIES)
--------------------------------------------------------------------------------
a) What are Props? (Definition):
   - Props stands for "PROPERTIES".
   - Props are inputs/arguments passed from a Parent component down to a Child component.
   - Real-World Analogy:
     Just like you pass arguments into a normal JavaScript function:
       function greet(name) { return "Hello " + name; }
     In React, you pass props into a component:
       <Greeting name="Rahul" />
   - CRITICAL RULE: Props are READ-ONLY (Immutable).
     A child component can NEVER change or modify the props it receives!

b) Why / When to Use Props?
   1. Component Reusability:
      - Write one component design (e.g. ProductCard, Button) and reuse it 
        multiple times with different data.
   2. Dynamic Content:
      - Instead of hardcoding text, UI changes dynamically based on the data passed.
   3. Unidirectional Data Flow:
      - Keeps data flow predictable and easy to debug (flows strictly Parent -> Child).

c) How to Pass and Receive Props:

   1. Passing Props (in Parent Component):
      - Pass data as attributes inside the JSX tag.
      - String values use double quotes: `name="John"`
      - Numbers, booleans, objects, arrays, and functions use curly braces `{}`:
        `age={25}` `isAdmin={true}` `skills={['HTML', 'CSS']}`

   2. Receiving Props (in Child Component):
      Method A: Using `props` Object directly
        function Student(props) {
          return <h3>Name: {props.name}, Age: {props.age}</h3>;
        }

      Method B: Using Destructuring `{}` (Industry Standard & Recommended!)
        function Student({ name, age }) {
          return <h3>Name: {name}, Age: {age}</h3>;
        }

d) Simple Step-by-Step Example:

   // File: src/components/UserCard.jsx (Child Component)
   function UserCard({ name, role, city }) {
     return (
       <div style={{ border: '1px solid gray', padding: '10px', margin: '5px' }}>
         <h3>{name}</h3>
         <p>Role: {role}</p>
         <p>City: {city}</p>
       </div>
     );
   }
   export default UserCard;

   // File: src/App.jsx (Parent Component)
   import UserCard from './components/UserCard';

   function App() {
     return (
       <div>
         <h1>Team Members</h1>
         {/* Reusing the same UserCard component with different props */}
         <UserCard name="Rahul Sharma" role="Frontend Developer" city="Ahmedabad" />
         <UserCard name="Priya Patel" role="UI/UX Designer" city="Surat" />
         <UserCard name="Amit Verma" role="Backend Developer" city="Vadodara" />
       </div>
     );
   }
   export default App;

e) Default Props (Fallback Values):
   - You can assign default values in case the parent doesn't provide a prop.
   * Example:
       function AlertBox({ message = "Default Notification", type = "info" }) {
         return <div className={type}>{message}</div>;
       }

f) Special Prop: `props.children`:
   - React automatically captures anything placed BETWEEN component open/close tags:
   * Parent:
       <Card>
         <p>This content goes directly inside props.children!</p>
       </Card>
   * Child:
       function Card({ children }) {
         return <div className="card-box">{children}</div>;
       }

g) Summary Table:
+--------------------+---------------------------------------------------------------+
| Criteria           | Details                                                       |
+--------------------+---------------------------------------------------------------+
| Full Name          | Properties                                                    |
| Purpose            | Pass data from Parent component to Child component            |
| Direction          | One-Way Data Flow (Parent -> Child only)                      |
| Mutability         | Read-Only / Immutable (Child cannot edit received props)      |
| Data Types Allowed | Strings, Numbers, Booleans, Arrays, Objects, Functions, JSX   |
| Best Practice      | Use Object Destructuring (`{ name, age }`) in component args  |
+--------------------+---------------------------------------------------------------+

18. REACT HOOKS & HOOKS VS PROPS
--------------------------------------------------------------------------------
a) What are React Hooks? (Definition):
   - Introduced in React version 16.8.
   - Hooks are special built-in functions (starting with "use", e.g., useState,
     useEffect) that let Functional Components use State and Lifecycle features 
     without writing Class Components.

b) Why Did Hooks Come? (Why were Hooks introduced?):
   Before Hooks, developers had to use Class Components for state and lifecycle.
   Hooks solved major problems:

   1. Removed the Confusion of the `this` Keyword:
      - In class components, binding methods to `this` was tricky, repetitive,
        and caused common bugs.
      - Functional components do not require `this`.

   2. Reusable Logic without "Wrapper Hell":
      - In classes, sharing stateful logic required complex patterns like
        Higher-Order Components (HOC) or Render Props, creating deeply nested
        component trees ("wrapper hell").
      - With Hooks, you can easily create Custom Hooks to share logic cleanly.

   3. Simplified Lifecycle Management:
      - Class lifecycle methods (`componentDidMount`, `componentDidUpdate`,
        `componentWillUnmount`) often split related code into different places.
      - The `useEffect` hook groups related side-effect logic together in one place.

   4. Cleaner, Less Boilerplate Code:
      - Functions with hooks require far less code and are much easier to read,
        test, and maintain than classes.

c) Rules of Hooks:
   1. Only Call Hooks at the Top Level:
      - Never call hooks inside loops, conditions (`if`), or nested functions.
   2. Only Call Hooks from React Functions:
      - Call them only inside React Functional Components or Custom Hooks.
   3. Naming Convention:
      - Hook names must always start with `use` (e.g., useState, useEffect).

d) Difference Between Hooks and Props (Simple Comparison):

+--------------------+--------------------------------+--------------------------------+
| Feature            | Props                          | Hooks                          |
+--------------------+--------------------------------+--------------------------------+
| Stands For / Core  | Props stands for "Properties"  | Hooks manage State (State      |
|                    | (passed into component).       | stores component data).        |
| Definition         | Arguments/data passed from a   | Built-in functions to access   |
|                    | parent down to a child.        | state and React features.      |
| Direction / Source | External (Parent -> Child).    | Internal (Inside component).   |
| Mutability         | Read-Only (Immutable). Child   | Mutable / Dynamic (Component   |
|                    | cannot modify received props.  | can update state via setters). |
| Purpose            | To configure & pass data to a  | To manage internal state, side |
|                    | component from outside.        | effects, and component logic.  |
| Syntax Example     | <UserCard name="Rahul" />      | const [count, setCount] =      |
|                    |                                |   useState(0);                 |
+--------------------+--------------------------------+--------------------------------+

e) Real-World Analogy:
   - Props: Like a package delivered to your doorstep. You can open and use it,
     but you cannot change what was sent inside it.
   - Hooks: Like appliances inside your kitchen (refrigerator, stove). You use
     them internally whenever you need to store or modify things.

19. STYLING IN REACT (INLINE, EXTERNAL & STYLED COMPONENTS)
--------------------------------------------------------------------------------
a) Inline CSS:
   - Pass styles directly as a JavaScript object to the `style` attribute.
   - Property names must use camelCase (e.g., `backgroundColor`, `fontSize`).
   - Values are strings (or numbers for pixel dimensions).

   * Example:
       function InlineDemo() {
         const headingStyle = { color: 'royalblue', fontSize: '22px' };
         return (
           <div>
             <h2 style={headingStyle}>Inline Heading</h2>
             <p style={{ color: 'gray', padding: '10px' }}>Direct inline style</p>
           </div>
         );
       }

b) External CSS:
   - Write standard CSS in a separate `.css` file and import it directly into
     the React component.
   - Use `className` in JSX instead of HTML's `class`.

   * Step 1: Create `Card.css`
       .card {
         padding: 16px;
         background-color: #fff;
         border: 1px solid #ccc;
         border-radius: 8px;
       }
       .card-title { color: #333; }

   * Step 2: Import & Use in Component:
       import './Card.css';

       function Card() {
         return (
           <div className="card">
             <h2 className="card-title">External CSS Card</h2>
           </div>
         );
       }

c) Styled Components (CSS-in-JS):
   - A popular library (`npm install styled-components`) that lets you create 
     reusable React components with styles attached using ES6 template literals.
   - Allows writing pure CSS with support for dynamic props and pseudo-classes.

   * Example:
       import styled from 'styled-components';

       // Create styled component
       const Button = styled.button`
         background-color: ${props => props.primary ? '#007bff' : '#6c757d'};
         color: white;
         padding: 8px 16px;
         border: none;
         border-radius: 4px;
         cursor: pointer;

         &:hover { opacity: 0.9; }
       `;

       function StyledDemo() {
         return (
           <div>
             <Button>Normal Button</Button>
             <Button primary>Primary Button</Button>
           </div>
         );
       }

d) Quick Comparison Table:

+-------------------+----------------------------+-----------------------------+----------------------------+
| Feature           | Inline CSS                 | External CSS                | Styled Components          |
+-------------------+----------------------------+-----------------------------+----------------------------+
| Syntax            | style={{ color: 'red' }}   | className="my-class"        | const Box = styled.div`..` |
| File              | Inside JSX file            | Separate .css file          | Inside JS/JSX file         |
| Pseudo-classes    | No (:hover, :focus, etc.)  | Yes                         | Yes                        |
| Media Queries     | Difficult / No             | Yes                         | Yes                        |
| Scoping           | Component only             | Global (name clashes risk)  | Scoped automatically       |
| Dynamic Props     | Yes (JS variables)         | Limited                     | Yes (via props in CSS)     |
| Extra Library     | None (built-in)            | None (built-in)             | Requires npm install       |
+-------------------+----------------------------+-----------------------------+----------------------------+

20. REACT HOOKS (TYPES, useState & useEffect)
--------------------------------------------------------------------------------
a) What are Hooks?
   - Special functions that let functional components use state and lifecycle features.
   - Must only be called at the top level (never inside loops, conditions, or nested functions).

b) Common Types / Categories of Hooks:
   1. State Hooks:
      - useState: Manages simple component state.
      - useReducer: Manages complex state logic with action-reducer pattern.
   2. Effect Hooks:
      - useEffect: Performs side effects (API calls, timers, subscriptions).
      - useLayoutEffect: Runs synchronously before the browser repaints screen.
   3. Context Hook:
      - useContext: Reads and subscribes to Context values without props drilling.
   4. Ref Hook:
      - useRef: Holds a mutable reference (or DOM element) that does NOT trigger re-renders.
   5. Performance Hooks:
      - useMemo: Caches / memoizes the calculated result of expensive operations.
      - useCallback: Caches / memoizes function definitions between re-renders.
   6. Custom Hooks:
      - User-defined functions (prefix with `use`) to reuse stateful logic across components.

--------------------------------------------------------------------------------
c) useState - Simple Explanation & Main Points
--------------------------------------------------------------------------------
* What it is:
  - Built-in hook to declare and update component state.

* Why use it:
  - Regular JavaScript variables reset to their defaults on every re-render and do NOT trigger a re-render when changed.
  - `useState` preserves data between renders AND re-renders the UI when updated.

* Syntax:
  const [stateName, setStateName] = useState(initialValue);

* Example:
  import React, { useState } from 'react';

  function Counter() {
    const [count, setCount] = useState(0);

    return (
      <div>
        <p>Count: {count}</p>
        <button onClick={() => setCount(count + 1)}>Increment</button>
      </div>
    );
  }

* Output / Behavior:
  - Initially renders: "Count: 0".
  - On button click: `setCount` updates `count` to 1, causing the component to re-render and display "Count: 1".

--------------------------------------------------------------------------------
d) useEffect - Simple Explanation & Main Points
--------------------------------------------------------------------------------
* What it is:
  - Built-in hook to handle "side effects" in functional components.
  - Side effects include: fetching API data, setting timers, manual DOM changes, event listeners.

* Why use it:
  - React components should remain pure during rendering (no side effects inside render body).
  - `useEffect` schedules side effects to run safely AFTER React renders and updates the DOM.

--------------------------------------------------------------------------------
e) All 4 Types / Variations of useEffect
--------------------------------------------------------------------------------

1. WITHOUT DEPENDENCY ARRAY:
   - Syntax:
     useEffect(() => {
       // Code runs after EVERY render
     });
   - Output / Behavior:
     - Runs once on initial component load (mount).
     - Runs AGAIN on EVERY re-render (whenever any state or prop changes).
   - Example:
     import React, { useState, useEffect } from 'react';

     function AutoLogger() {
       const [text, setText] = useState('');

       useEffect(() => {
         console.log("Component rendered or updated!");
       });

       return <input value={text} onChange={(e) => setText(e.target.value)} />;
     }
   - Output Behavior: Logs "Component rendered or updated!" on initial load and on EVERY keystroke typed in the input.

---

2. WITH EMPTY DEPENDENCY ARRAY `[]`:
   - Syntax:
     useEffect(() => {
       // Code runs ONLY ONCE
     }, []);
   - Output / Behavior:
     - Runs only once when the component is first mounted into the DOM.
     - Does NOT re-run on subsequent re-renders or state changes.
     - Best for: Initial API data fetching, one-time setups.
   - Example:
     import React, { useState, useEffect } from 'react';

     function InitialLoad() {
       const [data, setData] = useState("Loading...");

       useEffect(() => {
         console.log("Component Mounted!");
         setData("Data fetched successfully!");
       }, []);

       return <h2>{data}</h2>;
     }
   - Output Behavior: Logs "Component Mounted!" exactly once when page loads. `setData` updates text to "Data fetched successfully!" and effect never runs again.

---

3. WITH DEPENDENCY ARRAY `[dependency]`:
   - Syntax:
     useEffect(() => {
       // Code runs on mount + when dependency changes
     }, [dep1, dep2]);
   - Output / Behavior:
     - Runs once when component mounts.
     - Runs again ONLY when one of the specified dependencies (`dep1`, `dep2`) changes value.
     - If other state variables change, this effect does NOT re-run.
   - Example:
     import React, { useState, useEffect } from 'react';

     function DependencyDemo() {
       const [count, setCount] = useState(0);
       const [text, setText] = useState('');

       useEffect(() => {
         console.log(`Count changed to: ${count}`);
       }, [count]); // Only tracks count

       return (
         <div>
           <button onClick={() => setCount(count + 1)}>Count: {count}</button>
           <input value={text} onChange={(e) => setText(e.target.value)} placeholder="Type here" />
         </div>
       );
     }
   - Output Behavior: Logs "Count changed to: 0" on initial mount. Clicking the button logs "Count changed to: 1", "Count changed to: 2", etc. Typing in the input re-renders the component but does NOT trigger the log.

---

4. WITH CLEANUP FUNCTION:
   - Syntax:
     useEffect(() => {
       // Setup code

       return () => {
         // Cleanup code (runs on unmount or before next effect run)
       };
     }, [dependency]);
   - Output / Behavior:
     - The returned function executes right before the component unmounts (is removed from DOM) or before the effect re-runs.
     - Prevents memory leaks by clearing intervals, timers, and global event listeners.
   - Example:
     import React, { useState, useEffect } from 'react';

     function Timer() {
       const [seconds, setSeconds] = useState(0);

       useEffect(() => {
         const intervalId = setInterval(() => {
           setSeconds((prev) => prev + 1);
         }, 1000);

         // Cleanup function
         return () => {
           clearInterval(intervalId);
           console.log("Timer cleared / Component Unmounted!");
         };
       }, []);

       return <h3>Seconds: {seconds}</h3>;
     }
   - Output Behavior: Timer counts 1, 2, 3 every second. When this component is unmounted (hidden or navigated away from), `clearInterval` runs automatically and prints "Timer cleared / Component Unmounted!", stopping the timer to prevent memory leaks.

21. useRef HOOK (EXPLANATION, REAL-WORLD USES & COMPARISON WITH useState)
--------------------------------------------------------------------------------
a) What is useRef?
   - A built-in React Hook that returns a mutable object: `{ current: initialValue }`.
   - The `.current` property holds the value and persists across all re-renders.
   - KEY FEATURE: Modifying `.current` does NOT trigger a component re-render.

b) Syntax:
   const myRef = useRef(initialValue);
   // Access value: myRef.current
   // Update value: myRef.current = newValue (No re-render caused)

--------------------------------------------------------------------------------
c) Real-World Software & Web Application Use Cases
--------------------------------------------------------------------------------
1. Form & Input Management (Auto-focus & OTP Inputs):
   - Focusing an input automatically when a modal opens, or moving cursor to the
     next box in an OTP / PIN code verification screen.
2. Media Players (Audio / Video Streaming):
   - Controlling HTML5 `<video>` or `<audio>` elements directly (e.g. YouTube /
     Netflix players) using methods like `.play()`, `.pause()`, `.currentTime`.
3. Storing Interval / Timeout IDs (Stopwatch, Debounce, Idle Logout):
   - Keeping the timer ID returned by `setInterval` so it can be cleared from 
     any event handler without triggering extra re-renders.
4. Chat Applications (Scroll to Bottom):
   - Automatically scrolling to the latest message in a chat window using
     `chatEndRef.current.scrollIntoView({ behavior: 'smooth' })`.
5. Storing Previous State Values:
   - Remembering what a prop or state was on the previous render to compare changes.
6. Measuring DOM Dimensions:
   - Reading element width/height via `.getBoundingClientRect()` for tooltips,
     popovers, and custom dropdown positioning.

--------------------------------------------------------------------------------
d) Code Examples
--------------------------------------------------------------------------------

* Example 1: Direct DOM Access (Auto-focusing an input)
  import React, { useRef } from 'react';

  function InputFocusDemo() {
    const inputRef = useRef(null);

    const handleFocus = () => {
      // Directly accesses the DOM input element and focuses it
      inputRef.current.focus();
      inputRef.current.style.border = "2px solid royalblue";
    };

    return (
      <div>
        <input ref={inputRef} type="text" placeholder="Click button to focus me" />
        <button onClick={handleFocus}>Focus Input</button>
      </div>
    );
  }

* Example 2: Mutable Variable Without Re-rendering (Timer ID in Stopwatch)
  import React, { useState, useRef } from 'react';

  function Stopwatch() {
    const [seconds, setSeconds] = useState(0);
    const timerRef = useRef(null); // Holds interval ID across renders

    const startTimer = () => {
      if (timerRef.current !== null) return;
      timerRef.current = setInterval(() => {
        setSeconds((prev) => prev + 1);
      }, 1000);
    };

    const stopTimer = () => {
      clearInterval(timerRef.current);
      timerRef.current = null; // Clears reference without re-rendering
    };

    return (
      <div>
        <h2>Time: {seconds}s</h2>
        <button onClick={startTimer}>Start</button>
        <button onClick={stopTimer}>Stop</button>
      </div>
    );
  }
